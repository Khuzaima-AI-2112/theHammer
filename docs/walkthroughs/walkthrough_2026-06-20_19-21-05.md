# Walkthrough: Side-by-Side Accessibility Tree Capture

We have successfully implemented the semantic data extraction using the Content Script DOM Traversal approach. The extension now extracts information about interactive elements on the page silently and uploads it to GCS alongside the screenshot image.

## Summary of Changes

1. **Extension - Semantic Extraction** ([content.js](file:///c:/Users/chris/Desktop/theHammer/extension/content.js))
   - Implemented `extractSemanticData()` that queries the DOM for all inputs, textareas, selects, and elements with ARIA roles like `checkbox`, `radio`, `switch`, etc.
   - For each interactive element, it extracts:
     - The HTML tag and type/role
     - The current value or checked state
     - The associated label (via `for` attribute or `aria-label`)
     - The exact spatial bounding box (`rect`), enabling backend overlay/mapping logic to the screenshot.
   - Grabs any active text selection using `window.getSelection()`.
   - Listens for a new `EXTRACT_SEMANTIC_DATA` message from the background service worker.

2. **Extension - Capture Coordination** ([service-worker.js](file:///c:/Users/chris/Desktop/theHammer/extension/service-worker.js))
   - Updated the main `capture()` function to request the semantic data right before capturing the visible tab.
   - The data is seamlessly piped into the upload handlers (`uploadBlobWithSignedUrl` and `uploadViaProxy`), added to the offline queue payload, and included in the `multipart/form-data` fallback.

3. **Backend - Upload Handling** ([index.js](file:///c:/Users/chris/Desktop/theHammer/backend/src/index.js))
   - Modified `POST /upload-url` (the primary upload method). Since it is an authenticated backend endpoint, if the body contains `semanticData`, the API now directly saves it as a `.json` file in GCS using the same file path as the PNG.
   - Modified `POST /capture` (the fallback `multipart/form-data` proxy). Parses the appended JSON and saves it to GCS.
   - The `/capture` endpoint now adds `hasSemanticData: true` to the `uploads` document in Firestore.

> [!TIP]
> **Data Accessibility:** The JSON payloads are stored in the same path as the screenshot. If your screenshot path is `uploads/proj/123.png`, the accessibility tree data will be at `uploads/proj/123.json`.
