I have completed the technical implementation of **Sprint 6**, fulfilling all requirements for Session Events, Inactivity Tracking, and User Entitlements.

> [!SUCCESS]
> **Sprint 6 is fully implemented!** The extension now features an intelligent inactivity timer that prompts users after 45 seconds of idle time, logs inactivity events to Firestore, and tracks true active session time.

## 4. Backend Adjustments

- **Session Endpoint**: Created `POST /session-events` to securely ingest completed session metrics from the extension, calculate total session time, and compute `trueActiveMs`.
- **Inactivity Endpoint**: Implemented `POST /inactivity-events` to capture discrete periods of inactivity whenever an alarm is triggered or snoozed.
- **Entitlement API**: Updated `PATCH /admin/users/:userId` to support toggling the new `inactivityPromptEnabled` setting for individual users.
- **Aggregated Config**: Enhanced `GET /config` to merge the user-specific `inactivityPromptEnabled` override with the global defaults seamlessly, keeping extension logic simple.

## 5. Portal Enhancements

- **User Entitlement Toggle**: Added an interactive "Inactivity" checkbox directly to the `Users` table (`#view-users`). Admins can instantly override a user's prompt preference without leaving the roster view.
- **Visual Gap Highlighting**: Upgraded the `Activity` feed. When a user experiences an inactivity gap exceeding 45 seconds between captures, the UI injects a prominent visual gap indicator (red left border and `⏱ Gap: Xs` label) to alert analysts.

## 6. Extension Modifications

- **Manifest Permissions**: Granted `alarms` and `notifications` permissions.
- **Inactivity Timer**: Configured `chrome.alarms` to start a 45-second countdown upon each successful capture.
- **Smart Prompts**: If the user is inactive for 45 seconds, the service worker verifies their entitlement (`inactivityPromptEnabled`). If authorized, it surfaces an interactive `chrome.notifications` prompt with "Capture Now" and "Snooze" options.
- **Event Logging**: Any interaction with the inactivity prompt dispatches a telemetry payload to `POST /inactivity-events`, cleanly tracking idle periods.

> [!TIP]
> You can test the inactivity timer by enabling the toggle in the Portal for your user account, starting the extension, and waiting 45 seconds after a capture.
