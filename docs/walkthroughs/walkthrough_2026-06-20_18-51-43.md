# Firebase Auth & Workspace Migration Complete

I have fully implemented the transition from Cloud IAP to Firebase Authentication across both the Admin Portal and the Browser Extension.

## 1. Web Portal Integration
- Replaced the Cloud IAP polling with the Firebase UI Auth widget in `portal/index.html`.
- Users sign in directly via Firebase Auth.
- Created the **Workspace Settings** view. Admin users can create workspaces, invite members, and accept invites natively.
- All outgoing API requests now inject the `Authorization: Bearer <token>` header dynamically from the current Firebase User context.

## 2. Browser Extension Integration
- Added the `identity` permission to `manifest.json`.
- Dropped the "Personal API Key" requirement in favor of a full OAuth 2.0 flow.
- Added a `auth-ext.html` proxy page in the Portal to securely authenticate extension users via `chrome.identity.launchWebAuthFlow` and transmit the tokens back to the extension securely.
- `service-worker.js` automatically passes the `Authorization: Bearer <token>` for all screenshot captures and session events.

## Manual Verification Required
To verify these changes:
1. Copy your Firebase Configuration object (API key, project ID, etc.) from the Firebase Console into the placeholders in `portal/index.html` and `portal/auth-ext.html`.
2. Reload the Chrome extension.
3. Serve the web portal locally or deploy it to a staging URL.
4. Test the sign-in flow by signing in through the Web Portal and creating a workspace.
5. In the Chrome Extension, click **Sign In** inside the Settings menu to trigger the OAuth popup and ensure the token is saved properly.
