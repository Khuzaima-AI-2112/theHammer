# Customizable Per-User Inactivity Timers

I have completed the implementation for dynamic, per-user inactivity timers. As requested, the "Groups" feature has been deferred and documented in [sprint20.md](file:///c:/Users/chris/Desktop/theHammer/docs/planning/sprint20.md) so we can revisit it properly in a future sprint.

## What was built

- **Data Model**: The Firestore `users` collection now supports an `inactivityTimerSeconds` field (defaulting to 45).
- **Backend API**: 
  - `PATCH /admin/users/:id` now accepts `inactivityTimerSeconds` updates.
  - `GET /config` securely injects the user's custom timer duration so the extension can fetch it dynamically.
- **Admin UI**: The Users list in the Admin Portal now includes a number input box next to the Inactivity checkbox. Admins can update a user's timer here, and it saves automatically with a success toast.
- **Extension Logic**: 
  - The `service-worker.js` and `popup.js` scripts now rely on the backend-provided duration rather than a hardcoded `45` seconds.
  - The `chrome.alarms` are scheduled dynamically based on `settings.inactivityTimerSeconds`.
  - The `inactiveStart` time is computed dynamically based on the custom duration.
  - The copy text in both the popup modal and the system notification dynamically reflects the current user's timer setting (e.g. "It has been 15 seconds since your last capture...").

## Verification
You can now test this feature in the Admin Portal by setting a user's inactivity timer to a low value like `15` seconds, and verifying the extension prompts exactly after that interval.
