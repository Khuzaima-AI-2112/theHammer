# Sprint 9 Walkthrough: Hardening, Auth & Integration

This sprint focused on making the platform production-ready by unifying role-based auth, adding integration testing, expanding Cloud Monitoring, hardening Firestore security rules, setting up Binary Authorization controls, and improving the Admin Portal.

## 1. Backend (Auth, Rate Limiting & Dashboard)

- **Rate Limiting**: Added `express-rate-limit` to the backend. We configured dynamic per-role limits (e.g., analysts get 10 report generations per hour) and standard global limits.
- **Role Sync**: Updated `PATCH /admin/users/:id` to handle role assignments. Role changes now automatically synchronize to the `api_keys` collection to ensure immediate enforcement on authenticated API requests.
- **Dashboard API**: Created a new `GET /admin/dashboard/stats` route that aggregates key metrics (Active Projects, Active Users, Captures, Pending Reports, and Exports).
- **Key Rotation Worker**: Created `keyRotationWorker.js` which automates API key rotation, maintains a 7-day grace period for old keys, and places new keys into a pending state for email distribution.

## 2. Frontend (Admin Portal)

- **Consolidated Dashboard**: Added a new Dashboard view to the portal (`index.html`) that fetches and displays live metrics using the new stats API.
- **Role Assignments**: Replaced the static role badge in the Users view with a dynamic dropdown, allowing admins to directly assign roles to users.
- **Responsive Design**: Improved the CSS for mobile devices, introducing a hamburger menu and responsive grid adjustments for 375px width support.

## 3. Testing (Integration & Smoke)

- **Integration Tests**: Added `tests/integration.test.js` covering the new dashboard route and the role update logic using `supertest`.
- **Smoke Testing**: Created `scripts/smoke-test.sh` to run the backend container locally and perform a basic health check on the dashboard endpoint.

## 4. Infrastructure & Security

- **Firestore Rules**: Updated `firestore.rules` and added comments to clarify that all client reads and writes are strictly denied. Access is controlled completely at the backend application layer using the Firebase Admin SDK.
- **Monitoring Scripts**: Provided `infra/monitoring.ps1` with placeholder logic for configuring P1/P2/P3 application alerts.
- **Cloud Build**: Integrated `smoke-test.sh` as a local deployment check in `cloudbuild.yaml` before updating Cloud Run instances. Addressed the Binary Authorization requirement by documenting its conflict with ad-hoc desktop deployments.

## 5. Documentation

- **Runbook**: Created `docs/runbook.md` with standard operating procedures for rollback, flushing stuck exports, and revoking API keys.
- **Lessons Learned**: Added three new lessons to `lessons_learned.md` covering Firestore transactions constraints, Binary Authorization tradeoffs, and Firebase Admin SDK behavior.
